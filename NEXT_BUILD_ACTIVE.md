## P0 — HOURS-LONG, ACTUALLY EVOLVING MUSIC IN ALL 16 / 32 / 64 STEP MODES (owner FM-1 listening feedback 2026-11-04)

**Owner report:** On installed AQUORA 0.5.0, despite New Song and Reroll Sounds working, there is far too little noticeable continuing musical evolution—especially when comparing the 16-, 32-, and 64-step modes. Bassline and drums need to transform, but **EVERY role** (Lead, Bass, Pads/Drone, Harmony, Piano, Plucks, Choir and Drums) should keep evolving with meaningful variation during sessions that can run **for hours** without feeling like the same loop repeating. Preserve the already-liked sound and intention-appropriate palettes. This is a NEW next-build priority, NOT fixed by released 0.5.0.

### Verified source bug / root cause to address before designing more variation

- [ ] **FIX loop-size-dependent motif regeneration:** In `device/dsp/engine.c::trigger()`, 0.5.0 does `uint32_t s=e->sequence_step++;` and for loop lengths other than 16 overwrites `s=idx`, where `idx=e->loop_pos++` is bounded to 0..(length-1). Then regeneration is conditional on `(s&31u)==0 && s>0 && !e->freeze && rnd(e)<e->variation`. For **32-step mode**, `s` can only be 0..31, so the condition is **never true**; for 64 steps, the only eligible position is step **32**, and then only probabilistically. In 16 mode, `s` remains a continually increasing `sequence_step`, giving periodic opportunity at multiples of 32. Replace this coupling with explicit **monotonic transport step**, **local phrase step**, **bar/loop/section counts**, and **scheduled evolution boundary**; unit-test all 3 lengths and STOP/PLAY, loop resizing, pending tonic changes, Freeze on/off and saved-bank restoration.
- [ ] **Fix longer-loop predictability:** Existing `make_motif()` creates only 16 melodic cells, `motif_degree()` derives 32/64 positions by fixed arithmetic, bass enters on every eighth step (often exactly tonic), chords/choir/drone recur in rigid periodic placements, and `drum_trigger()` uses fixed grid hit types plus only simple bar-dependent accents. Implement **genuinely composed multi-bar sections** and variation opportunities for each part, not an identical 16-step loop stretched to 32 or 64 with trivial transposition.

### Music-first arrangement architecture: macro, meso, micro evolution

- [ ] **A musically coherent live arrangement director** per intention: independent seeded decision streams (not per-audio-sample randomization) and per-role evolving pattern state within the already existing 16-voice architecture. Use light-weight bar/phrase/section counters and preplanned event choices at step, bar or phrase boundaries. **Micro**: accents, rhythmic subdivisions, note lengths, rests, velocity, ornaments, articulation and occasional motif variation. **Meso**: bass answers and fills, drum variations, chord inversions/voicings, lead/harmony call-and-response, counter-motifs, piano/pluck arps and pad/choir swells, role entrances/exits and interlocking motifs over 2–8 bars. **Macro**: gentle arcs and transitions between calm/open, developing, lifted, sparse/reflective and resolution sections across 8–64 bars (lengths depend on intention), with changes in orchestration, rhythmic complexity, energy, harmonic color, density and dynamics. Return to recognizable musical motifs at intervals; don't erase all musical identity every 16 steps.
- [ ] **Evolve all 8 roles separately:** **Bass** must develop basslines with multiple pitch choices, rhythmic patterns, occasional held roots, passing tones, call/answer, rests and smooth harmonic voice leading (not just a tonic every 8 steps); **Drums** must evolve kick/hand/shaker patterns, accents, rests, fills, ghost notes, variation in arrangement and 16/32/64 multi-bar pattern memory without unrequested extra loudness or kit swaps; **Pads/Drone/Choir** shape evolving chord beds, quiet changes, note overlap and entrances; **Piano/Plucks** introduce complementary figures and changing arpeggios; **Lead and Harmony** carry motifs, variations, answers, counterpoint and sectional arrangement changes. Keep harmonic consistency, 13 intention mood identities, 432/440 tuning, selected reference Hz, Frequency Lock purity, Perfect Key and queued Change Key root.
- [ ] **16 / 32 / 64 must sound distinct** beyond wait time for another repeat: **16** = coherent short phrase with evolving accents, fills and occasional alternate second bar across repeated loops; **32** = true two-phrase call/response with bass/drum contrast and planned variations across bars, natural section transitions on recurring loop boundaries; **64** = four-phrase development: introduction/statement, expansion, contrast/answer, turnaround/fill/resolution with noticeable melodic/harmonic/drum progression before repeat. All three modes must still vary over hours. Switching lengths should transition musically at a scheduled boundary without corrupting counters or repeating the exact same opening every change.
- [ ] **Long-run musical memory / anti-repetition:** Keep compact bounded histories of recent motif signatures, bass patterns, drum patterns, harmonic motion, role combinations and recent section types; weighted choice should favor sufficiently distinct next phrases but deliberately reintroduce motifs for coherence. Avoid repeated identical arrangement/kit/melody from a constant start seed and avoid random notes with no relation. No history arrays that grow with elapsed listening time; wrap fixed-size rings to support 3–8+ hour sessions without memory creep, integer overflow, stale notes or audio processing spikes.
- [ ] **Easy performance controls, not an obscure menu:** EVOLVE must show **EVOLUTION LEVEL** (e.g. 0=Stable, 1=Subtle, 2=Flowing, 3=Adventurous; preserve an adjustable percent if desired), **SECTION/PHRASE** state, loop length 16/32/64 and visible **FREEZE** state; optional **EVOLVE ROLES** masks or per-track `Hold/Follow/Evolve` mode to protect favorite bass/drum/lead parts while other tracks develop. A one-action `NEXT VARIATION` / `NEW SECTION` request should schedule a music-safe transition at the next phrase/loop boundary. Clearly distinguish `NEW SONG` (new composition/timbre palettes), `REROLL SOUNDS` (timbre only, unchanged motif/arrangement) and `EVOLVE` (ongoing development, preserve song identity). User manual and onboard navigation must be understandable and accessible in <=3 obvious actions.
- [ ] **Respect freezes and manual performance:** Existing global `freeze` must genuinely halt evolution events (but transport/loop remains active) and not silently allow track-level mutation; per-role hold (if implemented) must freeze chosen role while permitting others to evolve. Preserve user sound locks, manual instruments/kit/FX/Nature settings and drum Presence / Level / Density / HIT; automatic evolution can subtly change performance dynamics inside user-set bounds but must NOT override manually selected patch/kit or intention reference/frequency, disrupt keys or change tempo without intent. STOP/PLAY must resume remembered arrangement; loading a saved bank should reproduce its current musical ideas and evolve from consistent saved RNG/section state thereafter. No repeated power-on clone song if New Song requested.
- [ ] **Cost discipline and stability:** Trigger decisions at bar/phrase/control-rate, cache next patterns, precompute chord/motif event tables, use fixed-size arrays/bounded voice allocation and avoid dynamic allocation, per-sample random decision layers, new reverbs, heavy FFT or unbounded sample voices.
