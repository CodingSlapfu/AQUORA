Replace this sprawling model with a small, comprehensible hierarchy, consistent control grammar, and visible path to all capabilities. Maintain a clear one-page overview of the entire feature map; the real firmware must implement it rather than simply documenting it.
- [ ] **Proposed primary structure (may refine for FM-1 usability):** **PLAY** = music, intention, currently selected frequency/Reference-vs-Lock mode, live KEY MODE shortcut, visualizer and track activity; **DRUMS** = all Kit, ON/OFF, Density 0–8, HIT, Level, Pan, Send, Mute/Solo and rhythm options together; **SOUND** = a visible category picker for Tracks/Patches, Motion (Lead/Bass Glide & Vibrato), Nature Beds, Tuning & Reference (Auto/Manual Hz and binaural), Sacred Bass/FX, not a 14-item blind cycle; **EVOLVE** = 16/32/64 steps, motifs, Freeze, current key/next-loop key, energy/variation; **MIX** = genuinely full-screen 8-track overview and legible 4-channel/selected-channel faders, meters, master, Auto Gain/Auto Level; **SETUP** = Lighting (AMB-1 On/Keys/Off/Dance), display/visualizer, banks, device options and plain-language Help. **PERFORMANCE** remains one GLO shortcut and also discoverable in SETUP, with direct AUTO/10/15/20 FPS adjustment, actual FPS/XRUN/CPU budget. Prefer ~6 clear top-level categories, with immediate ARP→DRUMS, HOME→PLAY, PLAY EDIT→KEY MODES, GLO→PERFORMANCE, existing save shortcut where sensible. Avoid adding more confusing category layers.
- [ ] **Deterministic, friendly hardware navigation:** ALGORITHM selects named primary destinations and always shows current page; SELECT normally selects the track/channel, except while an explicitly opened, visibly focused category picker is on-screen (show `TURN SELECT: CATEGORY` and confirm/back controls); PRESET remains scene on PLAY and patch/kit in relevant sound/drum contexts; K1–K4 always have legible on-screen labels and actual values and are never silently inert; EDIT opens a small contextual tab/category picker rather than blindly cycling unrelated groups; HOME reliably returns to PLAY or exits transient overlays; SEL acts as mute ONLY where labeled, never silently muting while selecting menus. Give clear visual and LED feedback, readable full names rather than cryptic abbreviations, on-screen help for every screen and safe confirmation for destructive edits. Never lose track of which track, category, mode, page or bank is currently active.
- [ ] **Fast access objective:** From power-on or any primary page, target **1 direct shortcut or 2–3 clear hardware actions** for common tasks: switch Play Along/Change Key, inspect current/pending musical key, adjust drum Density/HIT/Kit/Level, select/edit any of 8 mixer channels, toggle FX send, set Reference Layer/Frequency Lock and exact Hz, adjust Nature Beds, change 16/32/64 loop length, switch large Water Cymatics/Original, set LEDs, select FPS, load/save banks, and inspect audio XRUN/CPU. Test actual button count to reach each task, not subjective screenshots alone.
- [ ] **Consistency + visual redesign:** All screens share a coherent color/label system, persistent minimal status (intention/Hz, transport, mode, track where relevant), animated but audio-safe response to controls, selected tab breadcrumbs, clear setting ON/OFF/Auto states, proper 240×240 layout and contrast, larger mixer/panel areas, readable text and contextual explanations (`What changes when I turn this?`). Distinguish `KEY MODE` (Play Along/Change Key) from `FREQUENCY MODE` (Reference Layer/Frequency Lock), and musical key from intention Hz. New controls for LEDs, FPS, mixer, drums and visualizer MUST be integrated into this unified hierarchy, not added as more hidden SOUND groups.
- [ ] **Architecture, saves and verification:** Implement an explicit navigation state machine and typed screen/control mappings, no accidental shortcut collisions, missing K controls, blocking LCD/LED work in audio callback or DMA ISR, or unrelated parameter changes when switching tabs. Preserve valid 0.4.0 four-bank data, 13 scenes, recorded melodies, changes to lead/bass, FX, sources, user settings and old update/recovery compatibility; version/migrate only as needed.
