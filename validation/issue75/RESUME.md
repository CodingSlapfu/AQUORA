## Supported lease protocol
`tools/ownership_lease.py` uses dedicated `refs/heads/leases/<resource>` with lease.json, expiry and monotonically increasing acquisition epoch. Git compare-and-swap rejects stale owners and simultaneous acquisition. Read-only actions acquire nothing. Acquire returns a commit token; renew/check/release require that token and owner. Renewal replaces the token. Expired records permit a new acquisition; old tokens cannot renew or release afterward. `run --command ...` renews at TTL/3, stops only its own child on lease loss and releases on exit, persisting the latest token with --checkpoint. Tested using real bare Git CAS. Authenticated Git is required for CLI mutations; in Work, the GitHub connector can perform the equivalent Git blob/tree/commit and expected-SHA ref update. Direct Git push in this runtime has no credentials; use the connector for checkpoints.

Development leases fence their own branch. Publication requires a separate `aquora-publication` lease, a quiescence check of legacy publishers, CI concurrency and a fresh token check before each shared mutation. A new protocol cannot retroactively fence a legacy publisher; do not claim otherwise. Sites access is a separate resource.
