# AQUORA AIR — touchless Kaoss-inspired effect controller (2026-11-04)

Status: **researched next-build requirement and feasibility plan only**, no firmware or real-hardware proof yet. User says: "introduce the air mode here... fully optimize it this time and have it act as sort of a korg kaos pad. Allowing effect mix changes with just a wave of the hand over the bluetooth antenna area."

## Core expectation

Create a responsive gesture-to-effects instrument for the FM-1's Bluetooth antenna zone, where a hand approaching, hovering or waving changes **live effect mix**, like a minimal AIR Kaoss controller. Keep musical/audio engine intact; no pairing required *if* the chosen radio sensing method can passively observe a nearby transmitter. **Do not claim it can truly measure hand position, 2D X/Y, or even reliable proximity until verified on the device.** One RSSI-derived signal is only an approximate one-dimensional gesture/proximity control, subject to ambient emitter availability, reflections and strong noise. Velocity/direction inferred from changes is another derived feature, not a physically measured X/Y coordinate. Do not fake "hand movement" from a generic animation.

## Sources reviewed

- Korg KAOSS PAD KP3+ official: https://www.korg.com/us/products/dj/kaoss_pad_kp3_plus/page_1.php (simultaneous effect controls via X/Y, FX Release, Hold and Pad Motion; use design concepts only, don't copy software/assets).
- AQUORA `device/fm1.toml` CURRENTLY specifies `ble = false`, `cpu2 = true`, `cpu2_fallback = true` — radio is not enabled in published 0.5.0. AQUORA 0.5.0 measurements: ~83% audio+FX no drums / 84% with max drums and motion, callback p95 ~5.1ms of 5.805ms deadline at 16 voices; 0 observed XRUN delta in two snapshots, rare audible crackle elsewhere.
- FM-1 base `charlesvestal/fm1-base`: https://github.com/charlesvestal/fm1-base has Bluetooth vendor and optional own stack, `ble = true` / `ble_stack = "own"` / `ble_central = true` options, `plat_ble_enable`, `plat_ble_scan`, `plat_ble_found(int, name, int *rssi)`; own BLE scan receiver `bt/ble/ble_ll_central.c` samples RSSI words and `bt/ble/ble_scan.c` stores reports and calculates relative strength. **Caveat:** the documented `plat_ble_found` API finds advertisers of the BLE MIDI service, NOT a generic universal scan of any nearby phone. Do not claim a random phone is guaranteed to provide a readable signal. Independent MPL 2.0 implementation and licensing/SDK flash/RAM budget must be verified before adoption. No claim of current AQUORA compatibility.
- Older EIN-1 AIR design is conceptual history only: do not transplant its code or assume responsiveness was proven.

## Feasibility stages (must be completed before shipping a working AIR claim)

1. **Build/link and memory check**: First prove enabling BLE with pinned fm1-base/JieLi hardware and preserved AQUORA source/flash family fits firmware slot and RAM without disturbing USB updater, screen, voice engine, saved banks, 44.1kHz stereo or core-1 fallback. Prefer the smaller proven licensable stack *only if* it supports suitable source RSSI reliably. Record radio calibration and protection of boot/VM data; test BLE OFF brings radio quiet and adds effectively zero processing. If the radio option cannot fit, halt/shrink scope; never sacrifice OTA/recovery.
2. **Observe real signals, not theoretical proximity**: Build a minimal FM-1 radio diagnostic/test page capturing timestamped raw RSSI, advertisement counts, report freshness, sampling gaps, scan duty and CPU spikes with an explicitly selected supported BLE advertiser (a beacon/device that regularly broadcasts the required type). Measure hand still vs away vs near antenna vs wave in several orientations, multiple trials and room/device layouts, plus no transmitter, low signal, other nearby devices. No hand tracking if no stable source. Bound scan duty and no phone pairing if passive advertiser works.
3. **Adaptive sensor pipeline**: Baseline calibration / moving window, adaptive narrow-band/signal-delta estimate, median/outlier rejection, dual time constants (rapid attack, gentler release) and hysteresis/dead-zone. Modulation update **~10–25Hz or slower if needed**, performed at safe UI/control rate, not audio ISR; interpolate effect control smoothly within DSP. Detect signal timeout/stale RSSI or extreme noise; return to dry configured baseline or hold according to user setting, no sudden wet/feedback or volume spikes. Display signal quality, LIVE raw/smoothed level, CALIBRATE, no/weak/unstable signal and a real moving meter.
4. **Practical mono axis**: Map the one credible proximity/gesture value to X (=overall macro/FX amount). Optionally derive a separate Y (=hand speed/gesture intensity) only if clean enough to be trustworthy and explicitly label `WAVE` not spatial Y. Allow 1D even if velocity cannot be reliably measured; no fictitious touchpad coordinate. Movement over antenna can be hand distance/orientation, not absolute xyz.

## AQUORA user interaction

- **AIR OFF by default**. Make it an intuitive discoverable **PLAY > AIR** shortcut and **SETUP > AIR / FX MOTION**, reachable without hidden menus; no Play/Stop for toggling AIR. Controls: ON/OFF, CALIBRATE, SENSITIVITY, smoothing/response, source select/signal status, targeted **ALL / Lead / Bass / Pads / Harmony / Piano / Plucks / Choir / Drums** (drums mandatory), effect mapping, baseline wet %, modulation depth %, inverse response, HOLD/LATCH vs momentary, and graceful RELEASE back to saved setting. On device use clear 240x240 panel with **large HAND SIGNAL bar**, **FX MIX** actual percent, target and selected mapping, plus context-sensitive K1-K4 fields.
- **Factory mappings** should leverage *already-present real and optimized effects* first: `AIR WASH` modulates reverb/delay wet-send (default), `AIR ECHO` delay mix only, `AIR SPACE` reverb mix/depth, `AIR MOTION` crossfades reverb+delay in a bounded way. A `FILTER SWEEP` with cutoff+resonance is permitted only after a real efficient safe filter implementation exists; don't label a nonexistent filter as operational. Other richer destinations only if proven safe. Make both entire mix and selected track/drums routes musically usable and source/mute/solo aware.
- **Kaoss-like musical behavior**: hovering near the antenna increases a visible controlled wet %; removing hand smoothly returns to configured unmodulated FX mix; wave/fast movement can momentarily accentuate a second FX parameter if proven. Provide HOLD to sustain a chosen level, RELEASE to return naturally, and simple editable presets. Optional recording/playback of a fixed-size, tempo-aware gesture automation loop can be later scope only if available CPU, not a blocker for initial AIR.
- **Existing musical constraints**: Master volume safe; cap reverb/delay feedback and wet gain with bounded smoothing and limiter, prevent clicks/zippering, avoid doubling expensive FX processors; AIR acts on *parameter mix/send*, not adding extra persistent FX instances. Preserve user manual FX values, track sends and intention FX; AIR is an additive/overlaid performance control and doesn't overwrite saved values until explicitly stored. Manual override when knob touched, consistent Hold/Release. Never detune strict reference Hz, binaural stereo/beat difference, 432/440 tuning, Perfect Key or Frequency Lock. Pitch destination only if separately enabled and musically quantized/safe; not default.
- **Performance**: Hard DSP deadline 5805us for 256 samples. Radio IRQ/scan must have bounded priority, CPU/RAM/flash usage and radio-sample ring; no dynamic allocation, blocking scan, flash writes, or packet processing inside the audio callback. Off=zero radio processing; ON=measured low overhead under 16 voices, drums Density 8/Presence 100, full FX, Nature, both visualizers and single-core fallback. If low latency and clean audio cannot coexist, lower scan duty/gesture update or disable AIR; no false "working" claim.

## Required tests and release gate

- Prove hardware responsiveness with side-by-side **hand near/far/wave** raw vs filtered RSSI and actual audible FX change (not only display movement), multiple physical orientations + different supported advertiser source, and measure detection latency, false triggers/no transmitter behavior; explicit fail if no observable repeatable signal.
- Compare real FM-1 `AIR OFF` / `AIR ON idle` / `AIR MOVING`: callback mean/p95/p99/peak, independent audio/FX %, total CPU/core availability, 2-second/10-minute XRUN deltas, input drops, LCD-delivered FPS with full 16 voices (paired max drums and FX) plus mono/single-core fallback. No new XRUNs, pops, sustained crackle or major visual FPS loss. Validate radio-off electrical/processing silence where observable.
- PCM and listening A/B: gesture over antenna produces strong and controllable FX wet changes; after RELEASE returns to manually set FX, after HOLD stays appropriately; 13 intentions, all 8 tracks including Drums, muted/solo behavior, zero-depth and OFF exact baseline, signal loss, bad/no advertisements, 16/32/64 loops and midi/binaural/reference purity.
- Emulation: deterministic injected RSSI stream lets UI/test engine verify filtering, gesture, wet mix, silence, stale sample fallback, filter stability, control latency, persistence and rollback. Emulator simulation **never** proves antenna sensing on physical FM-1.
- Publish source + firmware + native/emulator acceptance + recovery with AIR documented as working **only after physical sensor test**. If physical verification must be owner-run, mark AIR as **EXPERIMENTAL / HARDWARE UNVERIFIED**, default OFF, with useful controls and no promise that a hand works without a compatible active BLE transmitter. Preserve shipped 0.5.0 rollback.
